# Extract Card Pipeline Into SPM Products

## Summary

Create a new local Swift package at `app/Modules/PokemonCardPipeline` with three library products:
`PokemonCardDetection`, `PokemonCardCropping`, and `PokemonCardStability`.

The existing `PokemonOcr` feature will depend on these products and keep only OCR screen, camera controller, preview, overlay rendering, OCR, and title extraction logic. Card detection, crop projection/cropping, and stability gating become reusable pipeline modules for upcoming work.

## Key Changes

- Add a new local SPM package `PokemonCardPipeline` with iOS 16 and Swift 6 settings matching the repo.
- Add `PokemonCardCropping`:
  - Owns `PokemonCardCropper`, `PokemonCardCropResult`, `PokemonCardCropError`, crop projection helpers, image normalization used by card pipeline code, and foreground-region analysis.
  - Keeps APIs that crop from an image or a normalized detected card rect.
- Add `PokemonCardDetection`:
  - Owns `PokemonCardShapeDetector`, detection/report/candidate/evaluation/metrics/quadrilateral/rejection types, Vision rectangle detection, and shape fallback scoring.
  - Depends on `PokemonCardCropping` for card aspect ratio, normalization, and fallback foreground candidate logic.
  - Public API remains Result-based: detect report, selected detection, candidate scoring, and validation.
- Add `PokemonCardStability`:
  - Owns `PokemonCardAutoCaptureGate` and its configuration.
  - Depends on `PokemonCardDetection` for `PokemonCardShapeDetection`.
- Keep `PokemonCardDetectionFrameThrottler` in `PokemonOcr` unless later pipeline work needs it outside the camera feature; it is camera scheduling behavior, not card detection/cropping/stability logic.
- Keep `PokemonCardShapeOverlay`, `PokemonCardCameraController`, `PokemonCardCameraPreview`, and `PokemonOcrScreen` in `PokemonOcr`; update imports and call sites to use the new products.

## Interface Changes

- Promote moved structs/enums/functions from internal to `public` where used across package boundaries.
- Preserve current names where possible to minimize app churn:
  - `PokemonCardShapeDetector`
  - `PokemonCardShapeDetectionReport`
  - `PokemonCardShapeDetection`
  - `PokemonCardCropper`
  - `PokemonCardAutoCaptureGate`
- Make nested configuration initializers public where the OCR target or tests need custom settings.
- Avoid dependency cycles:
  - `PokemonCardCropping` has no dependency on detection.
  - `PokemonCardDetection` may depend on cropping.
  - `PokemonCardStability` depends on detection.
  - `PokemonOcr` depends on all three products.
- Update `PokemonFeatures/Package.swift` to depend on `../PokemonCardPipeline` and add the three products to the `PokemonOcr` target and test target dependencies.

## Test Plan

- Move existing cropper tests to `PokemonCardCroppingTests`.
- Move existing shape detector tests and sample card resource to `PokemonCardDetectionTests`.
- Move existing auto-capture gate tests to `PokemonCardStabilityTests`.
- Keep overlay geometry, camera state, throttler, and OCR screen/state tests in `PokemonOcrTests`.
- Add or preserve coverage for:
  - Vision/fallback candidate scoring and rejection reasons.
  - 720x1280 image-space aspect regression.
  - Light tabletop sample detection.
  - Crop projection, clipping, detected normalized rect cropping, and fallback foreground cropping.
  - Stable detection, jitter tolerance, large movement reset, and overlapping source-shape changes.
- Verification:
  - Iterate with `just test-app`.
  - Run `just format-app`.
  - Run `just ready-app`.
  - Run `just ready` last.

## Assumptions

- The new package directory should be `app/Modules/PokemonCardPipeline`.
- The package should expose three products from one SPM package, not three separate package directories.
- Camera, UI overlay, and OCR title extraction stay in `PokemonOcr`.
- Cropping stays rectangular and buffered; no deskew/perspective correction is introduced in this refactor.
- Behavior should remain unchanged except for module boundaries and public access levels.
