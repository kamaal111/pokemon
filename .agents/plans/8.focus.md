# Card Focus And Blur-Gated Capture Plan

## Summary

Goal understood: improve OCR results when the camera is close enough that the Pokemon card text is visibly blurry, by making capture wait for a focused card instead of accepting the first stable card shape.

Research basis: Apple’s AVFoundation docs show focus point must be set before `autoFocus` / `continuousAutoFocus`, focus state can be monitored, minimum focus distance is exposed, and virtual multi-camera devices can switch lenses for close focus. Apple also warns scanning quality depends on resolution, light, distance, and blur. Document/OCR research consistently treats blur as a direct OCR-quality problem and recommends real-time document image quality scoring / best-frame selection, not blind post-capture deblurring. Sources: [Apple focus point](https://developer.apple.com/documentation/avfoundation/avcapturedevice/focuspointofinterest), [Apple capture-device focus](https://developer.apple.com/documentation/avfoundation/capture-device-focus), [minimumFocusDistance](https://developer.apple.com/documentation/avfoundation/avcapturedevice/3751762-minimumfocusdistance), [virtual camera switch-over zoom factors](https://developer.apple.com/documentation/avfoundation/avcapturedevice/virtualdeviceswitchovervideozoomfactors), [Apple TN2325 scanning quality guidance](https://developer.apple.com/library/archive/technotes/tn2325/), [VisionKit scanner behavior](https://developer.apple.com/documentation/visionkit/scanning-data-with-the-camera), [document image quality dataset/OCR blur](https://link.springer.com/chapter/10.1007/978-3-319-05167-3_9), [SEDIQA document quality/OCR blur](https://pmc.ncbi.nlm.nih.gov/articles/PMC8470036/).

## Key Changes

- Replace the current “stable rectangle means capture” rule with “stable rectangle + focused text region means capture.”
- Prefer a virtual back camera device when available, in this order: `.builtInTripleCamera`, `.builtInDualWideCamera`, `.builtInDualCamera`, then `.builtInWideAngleCamera`. This gives newer iPhones a chance to switch to a close-focus/macro-capable constituent lens.
- Increase video session quality from `.hd1280x720` to `.hd1920x1080` when supported, falling back to the current preset. Do not use photo preset for the live scanner because Apple notes very high photo resolution can increase exposure time and blur in low light.
- Keep continuous autofocus, near range restriction, smooth autofocus, and center exposure, but update the focus point dynamically to the detected card center instead of hard-coding `(0.5, 0.5)`.
- Add subject-area monitoring and a refocus path: when the card moves, when the selected detection center changes meaningfully, or when blur remains high for several frames, set focus/exposure to the card center and use `.autoFocus`, then return to `.continuousAutoFocus`.

## Implementation Details

- Add a `PokemonCardFocusQuality` module in the app camera layer or pipeline layer with:
  - `sharpnessScore`: variance of Laplacian on luminance.
  - `gradientScore`: Tenengrad/Sobel magnitude average as a second signal.
  - `brightnessScore` and `contrastScore` to avoid misclassifying dark/flat frames as merely blurry.
  - ROI support so scoring runs on the detected card crop and especially the top/title text band.
- Extend `PokemonCardPipelineFrameResult` with an optional focus-quality report:
  - `isSharpEnough`
  - `sharpnessScore`
  - `gradientScore`
  - `brightness`
  - `contrast`
  - `reason`, such as `focused`, `tooBlurry`, `tooDark`, `tooCloseLikely`, or `waitingForAutofocus`.
- Update `PokemonCardAutoCaptureGate` so it requires:
  - existing rectangle stability,
  - focus quality passing for at least 2 consecutive processed frames,
  - `AVCaptureDevice.isAdjustingFocus == false` when available,
  - no recent refocus request still inside a short settle window.
- Maintain a rolling best-frame buffer while scanning:
  - keep the best 5-10 recent stable detections by focus score,
  - if focus quality fluctuates, capture the highest-scoring stable frame rather than the most recent frame,
  - reset the buffer when card detection becomes unstable.
- Add user-facing scanning states:
  - “Hold steady” when geometry is stable but focus is still settling.
  - “Move a little farther away” when the card is very large in frame and sharpness stays low, indicating the lens may be inside minimum focus distance.
  - “More light needed” when brightness/contrast gates fail.
- Do not add deblurring as the primary fix. Keep any sharpening/deblur work post-capture and conservative, because document/OCR research shows quality gating and best-frame selection are more reliable than trying to reconstruct missing high-frequency text after defocus blur.

## Assumptions And Doubts

- Assumption: the current custom AVFoundation scanner should remain, rather than replacing it with VisionKit `DataScannerViewController`, because the app already has custom card shape detection, cropping, overlays, and Pokemon-specific OCR passes.
- Assumption: the first production threshold should be calibrated from repo samples and synthetic blur variants, not copied directly from generic web examples; Laplacian thresholds vary by resolution, lighting, and ROI texture.
- Remaining uncertainty: exact close-focus behavior depends on iPhone model and lens hardware. The implementation should log selected device type, `minimumFocusDistance`, zoom factor, focus mode support, and focus-quality scores so thresholds can be tuned from real device captures.
- Planning proof: inspected repo command surface with `just`, reviewed the current Swift camera controller, frame pipeline, stability gate, snapshotter, throttler, and text extractor, then researched current AVFoundation/VisionKit and document-OCR blur-quality guidance online.
