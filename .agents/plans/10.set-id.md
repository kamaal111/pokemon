# Detect Pokemon Card Set IDs

## Summary

Add set-id extraction to the Swift Pokemon card pipeline using Apple Vision text recognition on an enhanced bottom-left crop. The target behavior is that bundled samples resolve `eevee.jpg -> sv8a` and `shiny-charmeleon.jpg -> sv4a`.

Apple Vision references checked: [`VNRecognizeTextRequest`](https://developer.apple.com/documentation/vision/vnrecognizetextrequest) and Apple’s [Recognizing Text in Images](https://developer.apple.com/documentation/vision/recognizing-text-in-images). The local iPhoneOS 26.5 SDK confirms the modern knobs to use: `.accurate`, request revision 3, `recognitionLanguages`, `automaticallyDetectsLanguage`, `usesLanguageCorrection`, `minimumTextHeight`, and optional `customWords`.

## Key Changes

- Add `PokemonCardSetIdentifierExtractor` in `PokemonCardTextExtraction`.
- Crop only the bottom-left card area before OCR, using Vision-normalized bottom-left coordinates.
- Enhance that crop specifically for tiny set text:
  - normalize orientation
  - crop bottom-left set-id band
  - upscale with Lanczos
  - grayscale/high contrast
  - sharpen
  - optionally run a second thresholded variant if the first pass misses
- Extend `PokemonCardTextRecognizerConfiguration` with:
  - `usesLanguageCorrection: Bool`
  - `customWords: [String]`
  - `revision: Int?`
    Keep defaults matching existing text/name extraction behavior.
- For set-id OCR, configure Vision as:
  - `recognitionLevel = .accurate`
  - `revision = VNRecognizeTextRequestRevision3`
  - `automaticallyDetectsLanguage = false`
  - `recognitionLanguages = ["en-US"]` when supported
  - `usesLanguageCorrection = false`
  - `minimumTextHeight = 0.0`
- Parse OCR candidates with a conservative normalizer:
  - accept `sv` set IDs such as `sv8a`, `SV8A`, `SV 8a`
  - normalize output to lowercase
  - reject card-number-like values such as `217/187`
- Add `setIdentifier: String?` to `PokemonCardPipelineCapture`.
- Update `completeCaptureName(for:)` or replace it with a clearer completion method that extracts both `pokemonName` and `setIdentifier` from the crop image.
- Show the set ID in `PokemonOcrScreen` near the Pokemon name.

## Assumptions

- The input to set-id extraction is the already-cropped card image, matching current name/text extraction.
- Initial production scope is Scarlet/Violet-style IDs beginning with `sv`, because the requested fixtures are `sv8a` and `sv4a`.
- The implementation should not hardcode `sv8a` or `sv4a`; those values appear only in tests.
- No database or external set catalog is added in this pass.
