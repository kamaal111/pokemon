# Upright Pokemon Card Orientation Package

## Summary

Goal understood: the card pipeline should stop treating sideways/upside-down cards as if the attack area were the card, and should output a full upright card crop before focus scoring and OCR.

Add a new SwiftPM library target/product inside `app/Modules/PokemonCardPipeline` named `PokemonCardOrientationCorrection`. The package will correct cropped card images to upright orientation using OCR/text-position evidence, then the frame pipeline will pass the corrected crop to focus quality, capture storage, and name extraction.

Apple API research to carry forward:

- `VNRectangleObservation` exposes four normalized corners and is intended for rotated rectangles: [Apple docs](https://developer.apple.com/documentation/vision/vnrectangleobservation).
- `VNRecognizedTextObservation` subclasses `VNRectangleObservation`, so text observations can expose rectangle geometry: [Apple docs](https://developer.apple.com/documentation/vision/vnrecognizedtextobservation).
- `VNRecognizeTextRequest` supports automatic language detection on iOS 16+, matching this package’s minimum platform: [Apple docs](https://developer.apple.com/documentation/vision/vnrecognizetextrequest).
- Do not rely on `VNRecognizedText.boundingBox(for:)` for image-processing precision; Apple’s SDK header says those boxes are for UI purposes.

## Key Changes

- Add `PokemonCardOrientationCorrection` target/product with:
  - `PokemonCardOrientationCorrector.correctOrientation(of:) -> Result<PokemonCardOrientationCorrectionResult, PokemonCardOrientationCorrectionError>`.
  - Result fields: original image, corrected image, selected rotation (`none`, `clockwise90`, `clockwise180`, `counterclockwise90`), score, and compact debug evidence.
  - Error cases: invalid image and textRecognitionFailed, with localized descriptions.

- Extract the current internal Vision text recognizer into a shared target, for example `PokemonCardTextRecognition`, so both `PokemonCardTextExtraction` and `PokemonCardOrientationCorrection` use one OCR implementation instead of duplicating Vision setup.

- Orientation algorithm:
  - Normalize the crop image first.
  - Generate 0/90/180/270-degree candidate images.
  - Run fast/accurate enough Vision text recognition on each candidate with automatic language detection.
  - Score candidates by strong text evidence in expected upright card regions, especially the top title band, with lower weight for middle/bottom text so attack text does not dominate.
  - Prefer portrait card aspect after correction.
  - If scores are weak and the input is already portrait, return the original image rather than making a low-confidence rotation.
  - If the input is landscape, require the best 90/270 candidate to beat the opposite candidate by a configured margin before choosing it.

- Update detection/cropping so the full sideways card can reach the new corrector:
  - Allow shape detection to accept full-card landscape aspect ratios near the reciprocal Pokemon card ratio instead of rejecting them as unlikely orientation.
  - Update crop projection to fit either portrait `63/88` or landscape `88/63` based on the detected candidate aspect, then let orientation correction rotate the resulting crop upright.
  - Keep existing portrait behavior unchanged.

- Integrate into `PokemonCardFramePipeline`:
  - New stage order: detect -> crop -> orientation-correct -> focus -> stability/capture -> name OCR.
  - Store corrected `cropImage` in the `PokemonCardCropResult` passed downstream, preserving original crop metadata.
  - Add a pipeline error case for orientation correction failure only if correction cannot safely return the original image.

## Tests

  - Synthetic card images rotated 0/90/180/270 degrees; assert corrected output is portrait and chooses expected rotation.
  - Fake recognizer tests proving top-title text beats attack-area text.
  - Low-confidence/no-text portrait input returns unchanged.

- Add sample regression coverage:
  - Symlink `samples/N의 조로아-sideways.jpg` into the new test target resources using the existing `SampleCards` symlink pattern.
  - Assert the detector/cropper selects a full-card-sized landscape crop rather than the attack box.
  - Assert orientation correction returns a portrait crop and name extraction can find `N의 조로아` or at least places title text in the top band.

- Update pipeline tests:
  - Verify orientation correction runs after crop and before focus.
  - Verify captured crop and `completeCaptureName` receive the corrected image.

- Verification commands:

  - Run `just test-app` or the relevant app test recipe.

## Assumptions

- “New package” means a new SwiftPM target/product inside the existing `PokemonCardPipeline` package, not a separate top-level repository package.
- The first implementation targets 0/90/180/270-degree orientation and the current sideways/upside-down bug. Arbitrary perspective deskew is not required unless the sample or tests prove the crop still contains a visibly skewed card after this fix.
- The new package should correct the crop image, not the camera preview overlay.
